# HX4S20C HDMI 多媒体播放器（基础版）

本目录是从竞赛资料包中的 `lab_ex5_i2s` 复制并整合修改的独立工程，包含图片淡入淡出与水平滑动转场逻辑。

## 功能范围

- TF 卡读取 24-bit、未压缩 BMP，支持 640×480、480×640、800×600、320×240 四种源分辨率，并适配到 HDMI 640×480 输出。
- 读取最多 4 张图片，使用 EG4S20 内部 SDRAM 双缓冲。
- HDMI_B 输出 640×480@60Hz 视频。
- HDMI 同步输出 TF 卡中的 48kHz、单声道 16-bit PCM WAV 音频：前三张图片播放背景音乐，第四张播放语音。
- 画面底部叠加实时音频波形图，随左右声道 PCM 采样滚动更新。
- 按键切图和启停自动轮播。
- 按键调节图像参数（亮度 / 对比度 / 饱和度），屏幕上实时叠加参数面板。
- 图片缩放使用 FPGA 行缓存和最近邻重采样；帧写 FIFO almost-full 时暂停缩放器输出，为流水线中的像素预留空间。纵横比不匹配时保持比例并居中，480×640 图片左右以黑色填充。SDRAM 与 HDMI 输出帧仍为 640×480。
- 图片 1→2、2→3 切换采用约 0.27 秒渐暗、约 0.27 秒渐亮的淡入淡出；图片 3→4、4→1 切换采用水平滑动过渡，中间切换 SDRAM 显示缓冲区。手动切图和自动轮播使用相同规则。
- 转场控制保持忙状态直到动画结束；动画期间的手动切图请求会排队，避免重叠转场丢失完成握手。
- 板载 USB-UART 接收 ASCII 字幕：默认 `HX4S20 HDMI PLAYER`，115200 baud、8N1，发送 CR 或 LF 提交，最多 32 个字符；字幕在画面底部滚动，采用半透明深色底带和白色字形。

## 打开工程

使用 Tang Dynasty 打开：

`src/td_project/HDMI1.4b_Transmitter_v1.0.al`

目标器件为 EG4S20BG256。主要 RTL 位于 `src/user_source/hdl_source`，引脚和时序约束位于 `src/user_source/constraints_source`。请使用 HDMI_B 接口连接显示器。

## 板上按键与接口

工程端口名和板上丝印按键名称不同，按约束文件实际映射如下：

| 板上资源 | FPGA 引脚 | 工程信号 | 功能/备注 |
|---|---:|---|---|
| 50MHz 时钟 | R7 | `clk` | 系统时钟 |
| KEY1 | A2 | `rst_n` | 低电平复位；按住时系统保持复位 |
| KEY2 | B2 | `key1` | 手动切换下一张 |
| KEY3 | B1 | `key3` | 参数调节选择键：短按循环 亮度→对比度→饱和度→退出 |
| KEY4 | C1 | `key2` | 自动轮播开/关；调节模式下作「增大」 |
| TF CS | A12 | `sd_ncs` | SPI 模式 |
| TF CLK | A14 | `sd_dclk` | SPI 模式 |
| TF MOSI | A13 | `sd_mosi` | SPI 模式 |
| TF MISO | B14 | `sd_miso` | SPI 模式 |
| HDMI_B D0+/D1+/D2+ | G5/F1/E1 | `HDMI_D0_P/D1_P/D2_P` | TMDS 数据差分对正端 |
| HDMI_B CLK+ | C3 | `HDMI_CLK_P` | TMDS 时钟差分对正端 |
| HDMI_B DDC SCL/SDA | P2/R2 | `HDMI_DDC_SCL/SDA` | EDID 通道 |
| 板载 USB-UART RXD | F12 | `uart_rx` | PC 经板载 CH340 发送字幕至 FPGA；115200 8N1 |

**注意：KEY1 是复位键，不是切图键。** 例程内部名为 `key1` 的切图信号实际接到板上的 KEY2。
USB-UART 的 RXD/TXD 管脚映射依据《HX4S20 开发板手册-HDL版2410》第 11 页。

## 串口字幕

将板载 USB-UART Type-C 接到电脑，在串口终端选择对应 COM 口及 **115200 baud、8 数据位、无校验、1 停止位**。发送一行 ASCII 文本，以 CR 或 LF 结束即可更新字幕；最多 32 个字符，字母以大写字形显示。默认字幕为 `HX4S20 HDMI PLAYER`。仅支持 RTL 字库中定义的 A-Z、数字及少量常见标点；其他 ASCII 字符显示为空白。

## 上位机控制与图片直传

工程新增 Windows/Python 上位机，使用现有板载 USB-UART（F12 / `uart_rx`），不影响实体按键：

1. 安装 Python 3，在 `tools/host_pc` 下执行 `python -m pip install -r requirements.txt`。
2. 连接开发板 USB-UART，在设备管理器查看 COM 口；运行 `python host_app.py`，选择 COM 口并连接。
3. 上位机支持下一张、自动轮播开/关、参数面板、亮度/对比度/饱和度设置和字幕发送。
4. 选择 PNG、JPG、BMP、WebP 或 GIF 图片后，上位机会按比例缩放并居中补黑边为 640×480 RGB，直接写入 SDRAM 的非显示缓冲区，完成后切换到该图。

图片经 115200 baud 串口传输约需 80 秒。上传前请等待屏幕稳定显示图片并关闭自动轮播；传输期间不要断开串口或复位。上位机上传图只保存在 SDRAM，**不会写入 TF 卡**；重启或切换 TF 卡图片后，上传图不再保留。想要长期保留的图片仍应转换为 BMP 并复制到 TF 卡。

上位机控制协议使用 `0xA5` 前缀：`01` 下一张，`02` 轮播切换，`03` 参数面板切换，`10/11/12 + 1 字节`分别设置亮度/对比度/饱和度，`20 + 921600 字节 RGB`上传一帧。上传帧像素顺序为自下而上，以匹配现有 SDRAM 写入器的 BMP 行翻转处理。

开发板当前只有 UART 接收引脚，没有连接到上位机的 FPGA UART 发送反馈；界面显示的是电脑端发送进度，不是 FPGA 确认。若串口中断或传输不完整，请复位开发板后重新上传。

## 图像参数调节（亮度 / 对比度 / 饱和度）

1. **短按 KEY3**（工程信号 `key3`，板上 KEY3 / 引脚 B1）进入并循环选择参数：`普通 → 亮度 → 对比度 → 饱和度 → 退出(普通) → …`。进入后画面左上角出现参数面板，显示三行 `BRT`（亮度）、`CON`（对比度）、`SAT`（饱和度），每行带彩色进度条和 0~255 数值，当前选中行高亮。
2. 调节模式下（面板可见）：
   - **KEY2**（`key1`）短按 = 减小当前参数一步；按住约 0.5s 后连发减小。
   - **KEY4**（`key2`）短按 = 增大当前参数一步；按住约 0.5s 后连发增大。
   - 此时 KEY2/KEY4 的「切图 / 自动轮播」功能被屏蔽。
3. 再短按 KEY3 循环到「饱和度」之后即退出调节模式，面板消失，KEY2/KEY4 恢复原功能。
4. 默认值：亮度 128、对比度 128、饱和度 255（均为中性/原始效果）。参数实时作用于图像，退出后保持不变。

## TF 卡图片

1. 将 TF 卡格式化为 FAT32。
2. 可直接使用 24-bit、未压缩 BMP，分辨率为 640×480、480×640、800×600 或 320×240；FPGA 会在读取时缩放并适配到 HDMI 640×480。其他格式或尺寸可使用 `doc/convert/convert_images_to_bmp.py` 转换为 640×480 BMP。
3. 按下节说明先复制两个 WAV 文件，再复制最多 4 张 BMP 图片。
4. 先释放 KEY1 复位，再观察数码管状态；待首图载入后使用 KEY2 切图，或按 KEY4 开启/关闭自动轮播。自动轮播到点后会保留切图请求，直到 BMP 读取器空闲并开始加载，避免忙闲交接时丢失单周期请求。

数码管显示 `1` 表示 BMP 读取器处于空闲态，不是当前图片编号；扫描/读取期间会短暂显示 `2`、`3` 或 `4`。若扫描结束后没有找到支持格式的 BMP，则显示 `5`；检查 TF 卡根目录文件、BMP 格式和分辨率。
若读扇区后长时间没有收到数据起始标记，控制器会在 1 秒后复位 SPI 事务并重试当前扇区，避免永久等待。若数码管持续显示 `0` 或图片仍无法恢复，请按 KEY1 复位，并检查 TF 卡接触与供电。

### 图片音频

将 [prepare_audio.py](./tools/host_pc/prepare_audio.py) 运行后生成的两个 WAV 文件与图片复制到 FAT32 TF 卡根目录。播放器按原始扇区扫描文件，因此请先备份并格式化 TF 卡，再严格按下列顺序复制，避免音频文件碎片化：

1. `music_48k.wav`
2. `voice_48k.wav`
3. 最多四张 BMP 图片，按播放顺序排列

提供的 `C:\Users\LX\Downloads\music_48k.wav` 和 `C:\Users\LX\Downloads\voice_48k.wav` 可直接复制；播放器支持这两份文件各自的 WAV 头格式。音频文件必须是未压缩、单声道、16-bit、48kHz PCM。`python tools\host_pc\prepare_audio.py` 是可选的格式检查与标准化工具，生成文件位于 `tools\host_pc\audio_ready`。不要在复制文件后再修改 TF 卡内容。

按 TF 卡扫描到的前四张合法 BMP 顺序，对应以下音频：

| 图片顺序 | 音频 |
|---|---|
| 1～3 | `music_48k.wav`，循环播放；前三张之间切换时音乐继续播放 |
| 4 | `voice_48k.wav`，进入第四张时从头播放一次；切回前三张后音乐从头循环 |

音频在显示缓冲区实际切换时同步更换；首张图片显示前保持静音。上位机临时上传的图片沿用当前 TF 卡图片对应的音频，不会改变音频映射。若音频文件缺失或格式不支持，图片播放仍可工作，但 HDMI 音频保持静音。

播放器同时在画面底部并排显示时域波形和 FFT 频谱：左右声道 PCM 样本按 16 点平均后更新时域曲线，并以 8 位逐级归一化、复用单个乘法器的 16 点定点 FFT 生成 8 个频谱条，减轻曲线抖动并显示频率分布。两图共享紧凑的底部显示区域；此处理只作用于 HDMI 视频叠加，不改变音频播放数据或控制。

目录内的 `doc/convert/sync_to_sd.py` 会直接改写 TF 卡扇区。运行前务必备份数据，并确认脚本选中的确实是目标 TF 卡；不需要时请直接用资源管理器复制 BMP 文件。

### APUG011 SDRAM 参考设计对照

现已取得 APUG011 v1.2。官方参考 PLL 输入为 25MHz，输出为 12.5MHz、150MHz（0°）和 150MHz（180°）；`top.v` 将后两路分别用于 `Sdr_clk` 和 `Sdr_clk_sft`。该工程提供了一个可用于实验的 150MHz SDRAM 时钟基线，但不是当前播放器在 50MHz 输入下可直接复制的 PLL 配置。

APUG011 随包的 TD 5.6 时序报告显示 150MHz 时钟组分析了 4214 条路径且无 setup/hold 违例；但 180° 相移时钟组报告为 0 endpoints、0 paths。因此，这份报告不能证明它覆盖当前 TD 6.2 报告中的 SDRAM hard-IP DQ 路径，也不能单独证明提高到 150MHz 会修复当前 `ext_mem_clk` 时钟组约 `-6.301ns` 的 setup 违例。之前将 125MHz 判断为根因、并断言 150MHz 是修复方式的结论过强，仍需实验验证。

若进行下一轮对照实验，播放器的时钟目标建议为：

| 输出 | 候选频率/相位 | 用途 |
|---|---|---|
| `clk0_out` | 100MHz，0° | TF/SPI 域；保持 `sd_card_bmp` 的 `CLK_FREQ_HZ=100_000_000` |
| `clk1_out` | 150MHz，0° | SDRAM 控制器主时钟 |
| `clk2_out` | 150MHz，180° | SDRAM 相移时钟 |

这只是目标输出表，不是已经验证的 `sys_pll.ipc` 参数。应在 TD PLL IP Generator 中按 EG4S20BG256、50MHz 输入配置并生成 HDL，确认实际输出频率、锁定和 180° 相位后，再运行综合、布局布线并检查 DQ 路径；不能只手改 `.ipc` 或复制 APUG011 的 25MHz 输入参数。现阶段没有改动 `sys_pll.ipc` / `sys_pll.v`，也未加入 false-path 或 multicycle 例外。

当前 TD 生成的时序检查文件还为 32 个 SDRAM DQ 硬核引脚附加了 1–5ns 输入延迟；在确认这些模型约束与 DQ 实际采样/输出关系前，不应据普通逻辑时序结果忽略该路径。
